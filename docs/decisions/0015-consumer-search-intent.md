# T15 — Consumer shell and committed search intent

Native implementation ruling, 2026-10-25. Authoritative scope: design §§3,6,10–12 and the approved T15 brief. No frozen Superpowers tooling was used.

- React Router owns navigation. Only committed public `TransportSearchQuery` intent enters the bounded canonical `q` JSON parameter. No session, search, quote, privileged selector or host enters URLs. Duplicate parameters, unknown fields, empty/malformed JSON, unsupported catalog values and oversized links produce a visible recoverable state. Public schemas validate every field; catalog validates the routes, classes and providers it actually exposes. Operator restrictions remain syntactically validated and preserved because this catalog does not enumerate operator IDs; backend matching remains authoritative.
- A typed reducer separates draft, committed intent, date preview, generation, pinned/preview itinerary and modal draft. Modal and draft data are copied to avoid aliasing. Presets fill the draft only; Search is the explicit commit. Reload/back/forward restore committed intent, clear the old accepted response and allocate a new generation without launching a search. Preview does not navigate. Compatible cities/dates survive mode/scope changes; incompatible endpoints/classes/provider or baggage restrictions are cleared with a Persian explanation. Operator restrictions are preserved except across incompatible transport mode changes, which explain the clear.
- T15 submit sends the actual API `POST /api/v1/searches` (201), retaining its `SearchRecovery` in TanStack Query. A successful response must match both submitted generation and exact canonical query. The visible summary confirms the committed trip request only. No result cards, ranking UI, stream subscription, date-price explorer, hotel or real map binding is claimed; those remain T16–T18/T21. A prior owned operation ID survives failed commits for explicit supersession. Late operation IDs are used only to cancel the exact stale operation, never to adopt it.
- Session bootstrap is single-flight across StrictMode cancellation/retry. Its shared cookie-setting POST is not cancelled by one subscriber. Catalog reads allow one session-expiry bootstrap and one retry; no mutation is replayed. Fixed same-origin API methods validate requests and responses and distinguish typed API errors, transport failures, bad response contracts, and request validation. Abort signals reach fetch and aborted body reads remain aborts. Reset requires a native accessible confirmation explaining the destruction of this session's activity. It fences generations, aborts pending HTTP starts, waits at most1500ms, then calls the server's atomic own-session reset; valid committed intent may survive. No scenario endpoint exists, so the menu reports the actual scenario and links to admin instead of pretending to change it.
- Initial route and six mode/scope preset routes/classes come from API catalog IDs, never a browser inventory copy. Guest access is immediately usable. Origin enables only supported destination IDs. Party requires at least one adult, at most nine travelers and infants no more than adults. Age capability flags govern collection; no universal child/infant age range is invented. Invalid counts cannot allocate unbounded age arrays or enable submit. Server-authored age eligibility remains authoritative.
- Basic date inputs are explicitly Gregorian wire entry with a Jalali-first label, pending T16's wheel/calendar. `localDateAt` uses the origin zone for outbound day zero and destination zone for return day zero; `CalendarDate.add` yields inclusive day89 without UTC truncation. Both legs stay inside their local90-day window. Same-day return is structurally allowed. An outbound change that invalidates return clears it with a reselection explanation, never shifts it.
- One consumer ThemeProvider follows draft mode; graphics/route laboratories retain their own lazy providers. Initial composer navigation imports no Three or graphics runtime. The desktop left placeholder occupies46% from1120px; mobile omits it. The placeholder is explicitly schematic. All authored CSS colors use semantic tokens. The UI ref's `Pick<ViewTransition, 'ready' | 'skipTransition'>` avoids an ambient React Router/native DOM declaration mismatch without changing runtime theme behavior.
- `TOROBTICKET_WEB_API_PROXY` is an opt-in Vite same-origin API/admin gateway target for isolated development verification. Default API/admin ports remain4302/4301; strict web-only4313 proof uses the existing Docker4300 gateway with separate reviewer cookies. No existing services/database volumes are reset. The web Vitest project intentionally discovers both `.spec.ts` and `.spec.tsx` tests.
