# T11: Fresh referral evidence and atomic handoff

Approved during T11 implementation on 2026-10-24. Scope remains demo comparison/referral; no booking, payment, live provider, UI or migration.

- Public cookie-scoped endpoints are POST `/api/v1/referrals/prepare` (direct `ReferralSelection`), POST `/api/v1/referrals/confirm` (`intentId`, `acceptedQuoteVersion`, `idempotencyKey`), and read-only GET `/api/v1/referrals/:id` (`ReferralReceipt`). Strict runtime schemas reject arbitrary handoff payloads and session selectors.
- `RecheckRegistry` dispatches a session-scoped selection to a handler producing the shared `RecheckResult`. Transport is registered now; T20 can register its hotel engine. An absent hotel handler returns explicit non-retryable unavailable. The transport adapter dispatch runs only the selected provider.
- An internal `SearchRun` marked `referral-recheck` owns the provider/raw/normalization/offer FK chain. It shares the two-active-operation admission count, cancellation/reset fencing and startup interruption. All public search read/SSE/cancel/retry/predecessor/supersession seams reject this parent. No original comparison or date evidence is overwritten.
- Authority always resolves quote version 1 to its persisted real comparison snapshot and original query. Date observations and arbitrary internal evidence cannot authorize a handoff. New versions retain the same quote ID but point at their own fresh offer; their internal parent records the exact predecessor selection and original search ID. Concurrent stale input is rejected under the session lock.
- Admission freezes fixture/catalog/seed/anchor, scenario and revision, mapping revision and patch chain, actual override payloads, and source/policy revisions. A canonical SHA-256 fingerprint is checked again at finalization and confirmation, under the same session lock as admin/reset mutations. This includes override edits without a revision bump.
- Every successful fresh check appends a new immutable version, including unchanged business facts. Its observation time and 10-minute expiry are new. Previously expired selected quotes cannot be refreshed through this endpoint. Whole-party price, known mandatory fees, source binding, class, original filters, party and complete same-provider roundtrip are evaluated by the existing domain authority against persisted evidence inside the transaction.
- Exact old `previousQuote` is added to the changed wire result; exact new facts remain in `intent.quote`. Material comparison includes total, price breakdown and conditions, and ignores provenance timestamps/observation IDs. A substituted provider/service/class or journey is rejected instead of silently handing off another product. Unknown conditions remain unknown.
- Normalized fare IDs previously depended on observation-specific raw IDs. The approved correction uses canonical identity of provider ID, namespace, source service key and class. The authored mock dialects expose one fare per service/class; a future codec with multiple fare products must supply their actual distinguishing key. Total and terms are intentionally excluded because they can change at recheck. Offer/raw IDs remain observation-specific. Existing persisted evidence is never rewritten; incompatible legacy selections must be searched again.
- An intent stores exact selection, handoff payload, payload digest and context fingerprint, expiring after two real minutes. Confirmation samples the injected real clock **after** acquiring the session transaction lock, validates intent/quote expiry (`<= now` is invalid), version, digest, lineage, current context and domain eligibility, then creates exactly one immutable receipt/event under the unique session/idempotency key. A repeated successful key returns its original receipt even after expiry or context edits; a changed intent/version conflicts. The obsolete arbitrary-payload `createIntent`/`confirm` entry points are removed.
- Unavailable rechecks return alternatives only from that same original selected-query comparison, revalidated for current eligibility, whole-party source, latest version and expiry. These are comparison alternatives, not claims of another provider's fresh availability; each selection still requires a fresh check.
- Provider status/outcome/error and actual raw trace evidence are persisted. Intent/version/audit finalization is atomic. Storage failures interrupt the operation or remain queued for readiness recovery. Read-only receipt refresh adds no clicks, booking, revenue or conversion events.

Evidence and exact verification commands are in `docs/evidence/T11/task-11-report.md`. Independent review and packaged application verification belong to the controller's next stage.

## Review correction I1

The shared search termination transaction now reconciles any remaining `pending`, `running` or `collecting` provider rows after public snapshot projection. This includes internal recheck parents without a `providerStatuses` projection. Children use the existing cancellation vocabulary (`status: cancelled`, `reason: interrupted` or `cancelled` matching parent termination); other payload fields, raw/normalized evidence and already-terminal child results remain unchanged. The child updates, terminal event, termination audit and parent status commit atomically. Repeated recovery returns without additional writes once the parent is terminal. The same path serves service recovery, shutdown and startup; no provider operation is resumed.
