Native implementation ruling, 2026-10-25. Authority: design §§3–4/12, Task17, existing T08/T09/T15/T16 contracts. Root approved these joins before production implementation. No Superpowers tooling or frozen bookkeeping was used.

## Query and stream ownership

- The actual consumer mounts results only for an accepted operation ID and generation, below its composer. The atomic SearchRecovery already stored by the controller initializes the consumer; existing subscribeSearch owns validated SSE, cursor recovery, reconnect/polling and resource cleanup. Terminal cached snapshots do not reopen streams. Each recovery must match exact operation, generation and canonical committed query; old callbacks cannot write after cleanup. The browser imports public contracts/client/UI, not inventory, provider, persistence or a ranking implementation.
- Only server/domain order is displayed. Explicit sort changes and filter Apply authorize a new whole committed query through the existing controller and client-lifetime two-start pool. No browser comparator or local eligibility inference is introduced. Sort retains semantic date-price cache identity. Filter drafts do not alter the URL, request or composer before Apply.
- Refinement is disabled if the visible whole draft differs from the committed query. A Persian explanation labels existing results as the earlier committed trip and directs the traveler to Search first. This preserves unrelated unsubmitted trip edits instead of silently discarding them. The callback checks controller liveness, current generation and synchronous interaction lease, including before a React history/edit render can flush. Successful refinement updates composer, URL, generation and date pricing together.
- Filter controls cover whole-party budget in explicitly labeled toman (validated into integer rials), outbound origin-local departure window including midnight crossing, providers, observed operator IDs, class, complete-trip stops/transfers, refundable-only and flight checked baggage. No operator catalog is invented. Unselected provider/operator restrictions mean unrestricted. Affirmative unknown-condition eligibility remains server-owned.

## Adoption and safety

- A typed reducer retains separate adopted and latest authoritative recoveries. During initial collection it adopts server order. Focus inside a result, detail opening, fare selection or genuine results-area wheel/touch/keyboard/scrollbar interaction freezes inspection. One explicit action adopts later snapshots while retaining the freeze and a still-existing scroll anchor. Programmatic entry/adoption positioning does not count as a user scroll.
- Frozen cards, fare facts and representative explanations all describe the same adopted snapshot. Later coverage and an update notice may describe latest progress, but later representative facts never silently replace the adopted fare. The notice reports actual current valid-quote/group counts and asks the traveler to apply changes.
- Latest authority immediately revokes a removed/replaced/changed exact quote version; original real expiry also blocks it without another stream event. An exact quote selection retains group/quote/version identity after invalidation so the UI can explain why it is unavailable, rather than silently selecting another provider. Version identity and unchanged payload are both required for actionability. Selection handlers recheck Date.now synchronously, independently of rendered disabled state.
- Mounted deadlines follow original expiresAt values with one owned next-deadline timer chain, including consecutive fare expiries. A render never extends the observation or expiry. Cancelled operations cannot expose actionable fares. Incomplete mandatory totals stay separately labeled and have no selection action or cheapest claim.

## Facts, selection and presentation

- Each compact RTL card shows its fictional operator marker/name, explicit one-way or complete-round-trip scope, whole-party total, local departure/arrival date/time, ordered LTR route codes, duration including waits and flight stops/ground vehicle transfers. Return direction and a semantic per-segment timeline show each timezone, supplied stop/wait/vehicle-change and ground transfer. Dwell remains distinct from a transfer.
- Catalog Place names supply hover/focus tooltips and route labels; no external airport/brand lookup or invented real carrier logo is used. A flat native SVG transport mark and faithful label derived from the explicit fictional operator ID form the local operator identity. Catalog provider and class names remain authoritative.
- Selecting an actual provider/fare updates the exact total, both legs' baggage/refund/seat/cancellation/material terms, price breakdown and selection state together. Unknown stays unknown. Technical fare/version/source identifiers are available through optional provenance disclosure, outside the primary decision copy.
- Deterministic localized comparison facts resolve the adopted representative, baseline IDs and both quote versions. They say “so far” during incomplete coverage and never relabel representative comparisons as comparisons of a separately selected fare. Direct selected-fare terms are displayed instead.
- At most one server suggestion is shown. It must resolve both adopted quote references, current unchanged exact versions, nonempty all-success complete coverage and the exact current-search dismissal scope. Either side expiring/removal suppresses it immediately. Existing T09 has no nearby-date candidate snapshots, so current suggestions are same-query faster journeys only; no hidden speculative searches or fabricated nearby savings are added. Dismissal lasts for that search.
