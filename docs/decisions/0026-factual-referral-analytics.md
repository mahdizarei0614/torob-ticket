# 0026 — Factual referral accounting and lineage

Session metrics are explicitly all-provider/all-time counts: prepared=stored intents, changed/unavailable=completed recorded recheck outcomes, declined=explicit recorded traveler declines, confirmed=ReferralEvent rows. Provider distribution uses actual confirmed events. Filtered/paginated handoff and recheck tables use independent offsets; provider/type/from/to do not relabel all-session totals. No bookings, revenue or conversions are inferred; conversion reporting is not reported. Empty activity remains empty.

An explicit changed-offer Cancel sends a best-effort single cancellation observation for its known intent. Cookie scope and session row locking prevent duplicates/foreign cancellation; already committed intents return confirmed. Unconfirmed cancelled intents cannot later confirm. Existing same-key committed receipts replay first and remain immutable even after cancellation/expiry/configuration changes. Closing unknown in-flight preparation is not recorded as a known cancellation. Network-lost observations are not invented.

Detail follows receipt/intent and cancellation/recheck audit pointers into original quote/search, operation, source records and audit trail. Legacy unavailable hotel audits derive provider identity by joining the saved operation's exact selected immutable quote, with no history rewrite. Payloads are safe text; details cap source/event rows at100 with explicit totals, while lists use strict decimal bounded pagination. Counts of confirmed events change only at actual confirmation, never page views or refreshes.
