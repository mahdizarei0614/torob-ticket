# T14 — bounded dotted geography and explicit route geometry

Approved native implementation ruling, 2026-10-25. Scope: scene primitives/lab only; consumer state binding remains T18, layout T15, hotel modal T21.

- The public RouteScene consumes canonical Place/Itinerary and one outbound/return direction. Segment traversal preserves authored order and repeated places; stop facts keep their own authored order and unknown timestamps. Bus segments in flight itineraries remain distinct ground transfers. A missing bus path stays visibly unavailable rather than acquiring a straight-line surrogate. Endpoint-only illustrative and empty seams are separate from canonical itineraries; no priced itinerary is invented. Optional place selection and a DOM dropdown expose the future state-binding seam.
- Coordinates use equirectangular longitude/latitude degrees in one explicit central-longitude ProjectionContext. Projection, seam splitting, dots, markers, camera and inverse pointer input share this context. Longitude wraps and latitude clamps at poles. Split fragments receive boundary intersections; no edge crosses the world accidentally. Coincident fits have a positive minimum extent. Deliberate centering can use contextForPoints for long seam journeys. Projection context is caller-owned and must remain fixed during preview; change it with the deliberate fit key.
- CameraIntent belongs to semantic scene state, separate from the displayed itinerary. Only fitKey or the explicit originKey resets bounds. Theme, preview, direction, progress, context restoration and content scrolling retain intent. DOM zoom and two-pointer pinch are explicit; ordinary wheel/scroll does not zoom. Main map hiding belongs to desktop lab layout (<1120 px), while LocationScene remains available on mobile and in fallback. No orbit controls, auto-spin or animation loop.
- Flight geometry uses sampled elevated shallow curves; rail uses exact station segments. Bus/airport-transfer waypoints are explicitly fictional winding geometry, anchored exactly to canonical transport points. Paths are illustrative, never navigation or real road/rail claims. Progress is exactly 0/35/70/100 percent of comparison/referral and updates directly, including reduced motion; no booking completion claim.
- tools/generate-route-scene-fixtures.mjs is a build-side extraction seam only. Native Vite SSR loads existing fixture modules without opening a server (middleware, HMR/WebSocket off). It emits browser-safe bundled JSON plus a minimal graphics-owned test oracle. Existing canonical journey/appendAirportTransfer produce fixed-date showcase schedules. No fare algorithm or runtime Node/fixture dependency enters graphics. Source SHA256 hashes, revision, original provenance reference and illustrative labels travel with the asset. --check proves byte-for-byte deterministic regeneration.
- Dots are computed once at build time from original bundled Natural Earth Polygon/MultiPolygon topology and holes. World spacing 2° yields 3,888 points, Iran spacing 0.22° yields 3,212 points. The capped sampler rejects unbounded work. Hotel extents use the same bounded sampler cached per boundary; they remain authored display extents, never municipal borders. Assets retain original Natural Earth/OurAirports public-domain provenance and fiction labels.
- One T13 shared renderer remains authoritative. Scene-owned points/line/pixel geometry and semantic-token shader materials are reused until data changes, and explicitly disposed. Stable theme uniforms update without rebuilding resources; sRGB conversion/output happen once. Three programs at most are expected for the two shader types (route and sprite share source). DOM owns labels, timeline, coordinate inputs and selection; SVG retains static geography/route equivalence in context-loss/unavailable states. No remote map tiles or route services.
- /route-lab is lazy and production-available; Storybook reuses it. The laboratory labels precomputed source-derived schedules and exposes technical diagnostics deliberately. It does not pretend to be live API search results. Graphics tests/build and Storybook input caches include geography assets as well as GLSL; execution-based invalidation tests cover both.

## Completion rulings

- Full bus geometry covers the entire existing supported catalog, not only lab heroes:104 connections × 3 schedule variants, plus showcase and airport-change legs, produce 326 checked canonical journeys and 36 distinct ordered bus endpoint pairs. Native extraction checks every actual bus segment through the production geometry function. Public authored-only metadata lives at `/geography/route-geometry.json`; future consumers can fetch it without consuming lab itineraries. All three generated files have deterministic checks and 15 source SHA256 hashes. The real fixture airport change IST→SAW and the native-schedule lab THR→IKA transfer both retain separate geometry. Seven visible lab scenarios remain unchanged.
- Final route draw data is nonindexed GL_LINES, not a continuous strip: each source edge owns exactly two vertices. A test exercises the exact BufferGeometry builder consumed by SceneDrawing and verifies separate dateline fragments cannot acquire a connector. No route service or runtime path approximation is substituted.
- Native viewport borders initially caused a 1.2 px discrepancy between DOM label/inverse bounds and the actual GL content rectangle. An inset semantic-token shadow now paints the viewport boundary without changing its dimensions. Real mobile proof compares pointer inverse numerically, DOM custom-anchor offsets before/after actual pinch, and the actual framebuffer focus pixel.
- Clustered local landmark/accommodation labels spread into bounded DOM rectangles and use semantic-token leader lines to their unchanged projected points. The custom point remains directly anchored. Complete native dropdown selection remains available at every renderer state.
- Palette evidence awaits the actual native ViewTransition.finished promise. Sampling document.getAnimations before ViewTransition.ready is insufficient because the pseudo-element animation may not yet exist. Test instrumentation preserves the original transition callback/return and does not change application transition behavior.

## Independent-review correction — projected overview camera (P2)

The first review reproduced an overview defect: a caller projection centered on 54° moved Iran's dots near x0 while domestic geography/empty camera bounds stayed at x54. The overview now projects its authored 54° center with the caller's context. Default 22×17 composition is unchanged; if that extent crosses the caller's projection cut, the overview uses the complete [-180,180] projected frame so both Iran fragments remain visible. International geography already occupies that full frame and remains centered at x0 for custom contexts. Projection participates in bounds memoization, while camera updates remain restricted to explicit fitKey/originKey changes; preview, context prop changes and unrelated rerenders do not silently reset camera intent.

Six actual public-component regressions cover geography, empty and illustrative states, route-only pre-itinerary fit, deliberate fit/origin updates, stable previews and seam/world contexts. A native actual-component SSR probe checks every bundled dot, and a real-Chrome test injects only the public projection prop at the existing lab caller without changing production lab behavior. The initial failing native probe showed 0/3212 Iran dots at centralLongitude 54; after the fix it shows 3212/3212 for those domestic states and the seam context, plus 3888/3888 world dots in both tested custom contexts. Correction evidence is listed in the T14 report. No shader, projection formula, asset, schedule, renderer, dependency or default layout changed.
