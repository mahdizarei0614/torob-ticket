# 0087 — Direct Login and acquisition evidence

Date 2026-11-04. Owner instruction to implement the discussed integration.

TorobTicket issues local OIDC authorization codes with S256 PKCE and consent.
Explicit partner enrollment enables a choice page for confirmed referral receipts.
Ordinary navigation remains available. Provider SDK is server-only. The reference
provider maintains its own account/session store. Keys and protocol state persist
across API restarts and reset with their owning reviewer workspace.

An admin delivery inbox supplies local verification messages. Neither inbox codes
nor local account witnesses certify real phone ownership or external acquisitions.
External delivery/identity/account verification requires an independently operated
integration. No actual Torob federation is claimed.

Before contact disclosure record a validated prior-account exemption or the
provider's explicit acceptance of attribution. Salted account proofs bind the
verified phone and account to a commitment received before referral issuance.
The local reference provider's witnessed enrollment supports a confirmed acquisition,
while an external client completion remains pending independent evidence. Signed
claims alone cannot establish an external database's honesty. Unset acquisition
rates remain unpriced, zero remains valid, earlier rate snapshots are immutable.
Existing click fees and acquisition fees are reported separately. No implicit stacking
or credit is invented. No invoices, payments or booking claims are generated.

The pilot uses one-time existing-provider sign-in for logged-out users. Automatic
private matching against a committed roster is a future protocol extension.
