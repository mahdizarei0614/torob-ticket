# T13 — shared graphics host and browser lifecycle

Approved implementation ruling, 2026-10-25. Scope is the §12 renderer foundation and a deliberate laboratory, not the T14 map, T16 chart, or T21 hotel feature.

- One lazy R3F canvas owns a WebGL2 renderer. Drei View tracks semantic DOM rectangles and applies viewport/scissor clipping. GraphicsView accepts arbitrary R3F scene children; shared diagnostic geometry/material belongs to the laboratory, never each result card. The renderer clears the canvas before its clipped draws to prevent scroll trails.
- HTML retains labels, selection, controls and native dialog. The canvas ignores pointer events and uses the host DOM as its event source. Every view retains an SVG fallback, exposed for unavailable WebGL2, actual shader compile/link failure, and context loss. A failed canvas is hidden so stale GPU pixels cannot cover the fallback.
- ThemeProvider exposes a browser-safe generic bridge: resolved token subscribers run first, beforePaint subscribers second, all after root CSS attributes are committed. Stable typed RGBA vectors use Three's sRGB-to-linear conversion; GLSL emits through colorspace_fragment once into an sRGB renderer with no tone mapping. The last token state survives pauses and context restoration.
- The host uses frameloop=never and a single coalescing scheduler. Motion requires an explicit request, visible document and visible view, uncovered host, healthy context, and no reduced-motion preference. Hidden/offscreen/covered/lost scene subtrees use React Activity: state survives while layout effects and useFrame subscriptions are suspended. A scene-commit layout effect invalidates after reveal; a frame scheduled before the separate R3F commit is insufficient.
- Desktop DPR is capped at 1.75; mobile (viewport <=600 CSS px) at 1.5. A conservative low tier caps at 1 after 30 naturally requested frames have a median CPU submission duration >24 ms. The low tier stays latched until host teardown. Diagnostics distinguish CPU submission cost from GPU frame duration; no FPS or device-class claim is made. Diagnostic readbacks occur after the timing measurement and only when opted in.
- R3F owns renderer/event/context disposal. The laboratory owns its single geometry/material pair and explicitly disposes it. Camera objects are CPU-only and retained through Activity. The host cancels RAF and disconnects theme, context, media, resize, scroll, intersection and document listeners. Generation-local liveness guards prevent post-teardown state updates. WEBGL_lose_context restoration reinitializes Three's GPU resources without replacing DOM selection/camera intent.
- The stable dev and packaged route is /graphics-lab; shader=broken is confined to that laboratory. Storybook includes the same scene. GLSL ?raw imports use Vite in both builds and explicit declarations for library TypeScript. Nx graphics test/build inputs include source assets; the gallery also names graphics inputs. An execution-based cache regression proves shader-only changes invalidate all three targets.
- The discoverable e2e file is tests/e2e/src/graphics-host.spec.ts. GRAPHICS_E2E_PORT selects a validated isolated web-only server mode through the existing e2e target; ports4300–4302 are rejected. Direct Vite ownership prevents Nx child-server orphans; reuseExistingServer remains false. Actual hidden-tab proof uses an isolated Chrome profile with public CDP noDefaults=true because normal Playwright sessions force focus/visibility.
- Foreground hotel graphics above an opaque native dialog remain T21-owned. This foundation proves native modal input and background suspension; it does not claim an underlying document canvas can paint above an opaque top-layer dialog. T21 must explicitly choose foreground canvas composition/placement while keeping one owned context and native dialog semantics.

Pinned runtime source was inspected: Three 0.186.1, @types/three 0.186.0, R3F9.8.2, Drei10.7.9, React19.3.1. No dependency versions changed. Pinned R3F constructs the deprecated THREE.Clock; the browser warning remains visible and documented. The test-only CJS warning was traced to unused R3F imports through the library barrel; pure unit tests now import only the exercised modules, without suppressing warnings.

## Review correction — event and invalidation boundaries

Independent findings I1/I2 were accepted on 2026-10-25. Ready fallback content now retains layout but is visibility-hidden, non-hit-testing and inert; active fallback content remains visible and focusable. Root and each Drei portal install guarded standard store.invalidate methods through the public set/get API. This covers arbitrary declarative child prop commits and useThree(state => state.invalidate). Methods are stable per store lifetime; cleanup restores a prior method only if the bridge still owns the current method. Hidden/covered/lost scenes reject captured invalidators. Requests from inside a frame cannot create animation without the host's motion permission or during reduced motion.

The approved manual-host boundary excludes the package-level global invalidate() fan-out: pinned R3F intentionally ignores that function for frameloop=never. Scene authors use the standard useThree hook invalidator or the host controller; no demand/always loop was introduced. Memoized renderer props and host context prevent unrelated DOM/report updates from generating Drei prop commits. Canvas's DPR prop and the actual renderer now share the quality policy state, so resize configuration cannot restore an obsolete DPR.
