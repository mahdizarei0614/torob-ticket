# 0044 — Round-trip motion, chart lifecycle, profile and shared corners

Owner request, 2026-10-28. Current implementation brief. Specification 1.17 applies except where these eight presentation refinements supersede it. M7 remains partial, 29/35; T30 active.

1. Clear an incompatible destination as before, without the routine «مقصد با انتخاب تازه سازگار نبود؛ دوباره انتخاب کنید.» notice. Preserve actual input validation and never silently replace a city.
2. A complete selected round trip animates its actual outbound leg, a mode-specific flat turning maneuver, then its supplied return leg to the origin and blur-fades there. Flight banks, the locomotive and two wagons follow a rail turnaround, and the bus follows a road U-turn. Stops, transfer modes and return geometry remain canonical; do not manufacture a return for a one-way offer. Preserve manual mobile direction inspection and reduced/covered/hidden motion policy.
3. Date-price curves ease through first-draw/re-entry reveals, reshape from displayed geometry on date/inventory changes, and animate away when no priced data remains. Preserve unknown gaps, discrete prices, selected/hover markers, responsive pixel widths, GPU/SVG parity and finite scheduler ownership. Rename the range labels to «کمترین قیمت» and «بیشترین قیمت».
4. The signed-in account popover contains user details and a danger logout button with an inline icon. Guest sign-in remains reachable. Remove appearance controls from this popover and remove all consumer saved-search presentation/actions. Keep the toolbar theme control, local preference persistence, identity/session safeguards and existing server records/API contracts.
5. Remove the verbose changed-form result notice. Existing cards carry a concise invalid-price indicator for both changed intent and expired evidence; their selection/referral authority stays blocked until the matching trip is searched again. Genuine errors remain distinguishable.
6. Shared semantic radius/shape variables define squircle-style corners for cards, buttons, inputs, dialogs and segmented controls throughout authored UI. Use native CSS corner shaping with a rounded fallback. Preserve circles, map markers, chart bullets, focus rings and vendor-owned map styling.

Use scoped task agents and independent reviews. Record source/native verification, commits and the master/SDD/export checkpoint under `docs/evidence/adjustments/roundtrip-chart-profile/`. No remote push, publication, deployment, real provider integration, OAuth or runtime LLM.

Corner implementation reference: [CSS Borders Level 4, corner shaping](https://www.w3.org/TR/css-borders-4/#corner-shaping) and [Chrome implementation notes](https://developer.chrome.com/blog/implementing-corner-shape). Shape applies to the region defined by radius and follows native borders, clipping, shadows and outlines. Unsupported engines ignore `corner-shape` and keep the tokenized ordinary radius. The locally installed Chrome156 reports `CSS.supports('corner-shape','squircle') === true`; final native checks verify computed shapes on real controls/cards. Large surface radii are24px, standard cards/controls16px and small controls10px at the default16px root; true circles/pills explicitly retain `round`.
